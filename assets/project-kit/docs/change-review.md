# 变更测试与评审记录

复制本清单到合并请求或项目变更记录，并填写证据。未适用项写明原因，未验证项保持未完成；不能用勾选框代替独立评审。

## 范围与模块边界

- 本次解决的问题、对应需求：
- 涉及模块、拥有的数据及公开接口：
- 是否增加跨模块依赖、循环依赖、内部实现引用或直接写其他模块数据：
- `quality-gates.json` 是否需要调整，调整理由：
- 是否在同一变更中放宽阈值、删除测试或缩小扫描范围（必须单独说明）：

## 自动检查证据

- 候选提交／完整 SHA：
- 实际运行命令、结果和日志位置：
- 行数：单文件最多1000物理行；不通过压缩代码绕过。
- 复杂度：Python 默认函数分支分数不超过15；这是项目默认值，不是行业标准。
- 架构：声明层允许的静态导入依赖及文件级循环检查。
- 非 Python 代码采用的检查器、覆盖范围和未覆盖项：

## 人工评审

- 评审人／独立于实现者的身份：
- 结论：待评审／通过／要求修改。
- 职责是否单一，命名和接口是否清楚，拆分是否只是机械分片：
- 复杂度虽未超限，是否仍有过深嵌套、重复判断或难以理解的状态组合：
- SQL、动态导入、运行时注册、跨模块数据写入等静态检查盲区：
- 数据迁移、权限、金额、数量、审批规则或库存变更的专项评审：
- 尚未解决的问题及接受风险的人：

未取得真实独立评审时必须写“未独立评审”，不能把实现者自查或代理自评当成外部批准。

### 填写示例（仅格式，不是验收记录）

独立评审通常指**非本次实现者**、有相关能力的同事、维护者或外部顾问；可以属于同一项目，不要求来自其他公司。只有实现者本人时，应安排外部复核或明确保持未独立评审，不能自己批准自己。另一 AI 的只读意见可作为补充，是否满足团队审核政策需单独确认。

```text
候选提交：<git rev-parse HEAD 得到的完整 SHA>
变更链接：<仓库>/compare/<base SHA>...<candidate SHA>
CI 链接：<该 SHA 对应的工作流运行 URL>
本地结果：python3 scripts/check_quality.py；exit=<实际退出码>；日志=<路径>
独立评审人：<非实现者的姓名／账号与职责>
评审结论：待评审 / 通过 / 要求修改；时间=<实际时间>
遗留问题：<issue 链接、负责人及是否阻断>
```

| 类别 | 示例证据（请替换为真实结果） | 状态 |
| --- | --- | --- |
| 正常与边界 | `<测试文件>::<测试名>`，数量0／上限／上限+1 | 待验证 |
| 禁止路径 | 普通员工调用主管接口被拒绝的 HTTP 测试 | 待验证 |
| 并发／幂等 | 两个相同入库请求只增加一次库存的数据库断言 | 按本次变更判断 |
| 不适用项 | 例如“本次仅改 README，无数据库写入”及理由 | 明确不适用 |

评审或测试后修改了代码，应生成新的候选 SHA，重新验证受影响部分；不能把旧提交的通过记录直接套到新提交。
